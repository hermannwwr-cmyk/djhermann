# DJ Turntable Game: Handoff Brief

Status: **step 1 (single-player game) is built and playable.** Platform and host are decided (see "Decisions"). Steps 2 and 3 (multiplayer) are not started.

## Goal

A mobile DJ turntable rhythm game where the player acts as the DJ on a song. Multiplayer is the headline feature: several players, each on their own phone, play the same song at the same time and stay in sync, even when the phones sit side by side.

## Gameplay (agreed direction)

- Two decks (A and B) with spinning platters. Dragging a platter scratches.
- Mixer: per-deck HI/MID/LOW EQ (low can be fully killed), a filter knob (low-pass/high-pass sweep), channel faders, a crossfader, tempo (pitch) fader, CUE, PLAY, SYNC, nudge buttons and ECHO.
- Waveform view with a beat grid for each deck, used for beatmatching.
- Rhythm lane: notes scroll to a hit line in time with the playing deck's beats. Four lanes, each a sound pad (e.g. clap, air horn, zap, boom). Timing judged Perfect / Great / Good / Miss, with combo and score multiplier.
- Crowd hype meter: goes up with good hits and completed missions, down with misses. Penalties for **dead air** (nothing audible) and **trainwrecks** (two audible decks out of tempo or phase).
- DJ missions during a set: start the other deck, beatmatch it (manually or with SYNC for fewer points), crossfade over (bonus for a smooth mix or a bass swap), stop the old deck, kill the bass for a bar and drop it on the 1, scratch, filter sweep.
- Modes: a timed gig with missions, results and a grade, and free play.
- Mobile-first: touch controls, big pads, portrait-friendly layout.

## Music and copyright (important)

- The user wants Gryffin songs. **Gryffin songs must not be bundled, uploaded or streamed between players.** They're copyrighted.
- **Built-in music:** original tracks generated by the game in a melodic house / future-bass style (e.g. render synth tracks with an OfflineAudioContext at load). These are safe and identical on every device.
- **"Load your own music":** players load MP3/WAV/M4A/FLAC files they own from their device. Files stay local and are never uploaded. DRM files from Spotify, Apple Music, YouTube Music or Tidal won't load; tell the player so.
- Own files need automatic BPM and beat-grid detection, plus a manual fix: TAP tempo, ½×/2×, and grid nudge.
- Optional later: add CC0 or CC-BY tracks with credits. Sources the user was given: OpenGameArt, Free Music Archive (filter to CC0/CC-BY), Pixabay Music. NCS sounds the closest to Gryffin, but its free terms target videos and streams, so check before using it in a game. Jamendo is mostly non-commercial.
- Streams or videos of gameplay that use Gryffin tracks may get copyright claims.

## Multiplayer design (agreed)

Players join a room with a code. Two modes:

1. **Party mode (default for same-room play):** one phone or a Bluetooth speaker plays the audio. Every other phone is a controller that shows its own notes, synced to the host's clock. One sound source means no echo. With own files, only the host needs the song.
2. **Every phone plays:** each phone plays the song itself, which works best with headphones. Needs:
   - **Shared clock:** NTP-style ping exchanges with the server, keeping the lowest-round-trip samples. The host schedules "start at shared time T + a few seconds" and each phone starts audio exactly then on its audio clock.
   - **Per-device latency calibration:** a tap-along to a click. Android and Bluetooth output delay varies a lot (tens to hundreds of ms).
   - **Drift correction:** compare playback positions periodically and adjust playback rate slightly.
   - Target: within roughly 10–20 ms, or side-by-side phones audibly echo.
   - **With own files:** each player must own and load the same song. Verify it's the same song (duration, fingerprint or hash) and align on the first detected beat, because copies from different stores can start with different amounts of leading silence. Only timing and game state are sent between devices, never audio.

Also discussed, as a fallback or extra: two players on one device (split lanes, or one player on notes and one on mixing), and a turn-based battle mode.

## Platform and tech

- Proposed: a **mobile-first web game (PWA)** that runs in the phone browser and installs to the home screen. It could be wrapped as a store app later. **The user hasn't confirmed this yet.**
- Needs a real-time **WebSocket** server for rooms and clock sync. A Claude Artifact page can't do this (WebSocket/WebRTC are blocked there), so it must be a real hosted site.
- Mobile web audio gotchas: audio has to be unlocked by a tap; on iOS, the silent switch can mute web audio; background tabs suspend audio.

## Hosting options given to the user

| Host | Notes |
|---|---|
| Cloudflare Pages + Workers / Durable Objects | **Recommended.** Free tier, never sleeps, built for multiplayer rooms, fast worldwide. More setup. |
| Render | Simplest: one Node server for the game and WebSockets, deploys from GitHub. Free tier sleeps after about 15 minutes idle (30–60 s cold start); about $7/month paid. **Recommended as the easy start.** |
| Railway | Easy, doesn't sleep; trial credit, then about $5/month. |
| Fly.io | Pay as you go, a few dollars a month; more technical. |
| Firebase / Supabase Realtime | No server code; less timing control. Fine for party mode, weaker for every-phone sync. |
| GitHub Pages / Netlify / Vercel | Static game page only. No live server (Vercel has no WebSockets). |

Prices and free tiers change, so check them before committing. The user must create the hosting account and connect it to GitHub themselves.

## Decisions (confirmed by the user)

- **Platform: phone-browser PWA.** It installs to the home screen and can be wrapped as a store app later (e.g. Capacitor).
- **Host: Cloudflare.** Cloudflare now points new projects to Workers with static assets rather than Pages, so `wrangler.jsonc` deploys `dist/` as a Worker's static assets. Step 2 adds a Worker script and one Durable Object per room to the same project. The config was not checked against Cloudflare's docs (they were unreachable from the build session), so check it on the first deploy.

## Step 1: what exists

Vite + TypeScript, no UI framework (DOM, CSS, Canvas 2D, Web Audio). Every module codes against the contracts in `src/core/types.ts`; `src/app/` wires them together.

| Module | Directory | What it does |
|---|---|---|
| Core | `src/core/` | Shared types, beat-grid maths, mixer laws, frame loop, navigation, settings |
| Audio engine | `src/audio/`, `public/worklets/` | Deck worklet (scratch, motor, CDJ CUE), latency-compensated clock, EQ/filter/echo/limiter, pad sounds |
| Built-in music | `src/music/` | Six original synthesised tracks (116–128 BPM) and all one-shot sounds, rendered in a Worker |
| Analysis + library | `src/analysis/`, `src/library/` | BPM/beat-grid detection, waveforms, beat energy, sections; own files kept locally in IndexedDB |
| Rhythm | `src/game/rhythm/` | Note charts, the note highway and the four pads, judging and combo |
| Gig | `src/game/gig/` | Missions, transitions with rescues, hype, dead air/trainwreck, scoring, the tutorial, free play |
| Console | `src/ui/console/` | The realistic decks and mixer, the waveform display |
| HUD | `src/ui/hud/` | Stage, score/hype top bar, mission line, the control guide, callouts, pause menu |
| Screens | `src/ui/screens/` | Title, home, setup, My Music (import + beat check), settings, calibration, how-to, results, icons |

Run it: `npm install`, then `npm run dev` (open the printed URL on a phone on the same network, or in a desktop browser at phone size). `npm test` runs the unit tests (367), `npm run build` builds `dist/`. Each module also has a dev harness page under `dev/`.

Deploy: `npm run build`, then `npx wrangler deploy` (needs a Cloudflare account and `wrangler login`), or connect the GitHub repo in the Cloudflare dashboard with build command `npm run build`.

Verified in headless Chromium (desktop CPU, simulated phone screen): the tutorial and a full three-track gig play through the real UI with no errors, following only the on-screen guide; the production build runs and registers its service worker. Measurements for each module are in the commit history.

**Not verified yet (needs a person and real phones):**
- Nobody has listened to the music or the sounds. The vocal-chop leads are the biggest risk.
- No real iPhone or Android test: performance, touch feel, the iOS silent-switch workaround, Bluetooth latency.
- All game timings (mission windows, hype drain, the length of a mix) were tuned against simulated players.
- Beat detection was only tested on synthetic audio, not real MP3/M4A/FLAC files.

**Known small issues:**
- The tutorial's pads step can't spotlight the pads (there is no control id for them); it is guided by the status line only.
- The device back button doesn't close the free-play track picker (it opens the pause menu instead).
- Long track titles can make some status lines run past the 50 characters the mission line fits.
